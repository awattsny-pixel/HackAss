# PX-2c: sign-in, recovery, password setup, email-link states and the session indicator (implemented locally)

Branch `px2b-auth` (PX-2c on top of the accepted PX-2b). **Uncommitted. Local only: no hosted contact, no migration, no saving/AI/payments.** Visual language is the approved UX-08 design (tokens, radii, Hack artwork, 44 px controls, focus ring); nothing was redesigned.

## 1. What exists
| Where | What |
|---|---|
| Top bar (every experience page) | **Account chip**: "Checking sign-in…", "Not signed in" + Sign in, "Signed in" + Sign out (+ "Choose your password" when an invitation is unfinished), "Signed in · can't check right now" + Try again, "Can't check sign-in right now" + Try again. A polite live region. |
| `/account/sign-in` | email + password; client navigation after success (`router.push`), so the unsaved prompt stays; states: wrong credentials, rate-limited, temporarily unavailable, incomplete form, already signed in. "Registration is closed for now" notice; no sign-up link anywhere. |
| `/account/recover` | request a reset link; the confirmation is the same for a member and an unknown address; states: invalid email, rate-limited, unavailable, sent. |
| Email-link pages (standalone documents, opened from an email) | ready (invite / recovery / email change), **explicit account-switch** notice ("Sign out and continue" / "Stay signed in and go back"), password form, weak-password message, expired or used, invalid, registration closed, rate-limited, temporarily unavailable ("We couldn’t confirm whether this completed. Try again. If the link has expired or was already used, request a new one."). Same tokens, Hack artwork and 44 px controls as the app. |
| Session logic (`src/ui/account`) | pure reducer + provider: first check on load, **re-check on focus / visibility / back-forward restore / back online** (at most once per 10 s, never overlapping, each request capped at 6 s). |

## 2. Rules the implementation enforces
* **An Auth outage never signs anyone out.** A member who cannot be re-checked stays shown as signed in ("degraded") with a notice and a Try again button; only a definite "anonymous" answer after having been signed in shows "You have been signed out. Your unsaved work on this page is still here." Unexpected answers are "unavailable", never "anonymous".
* **The unsaved prompt is out of reach of the account code.** The session provider uses the experience context only to show a toast; the sign-in and recovery screens do not import it (source test). Sign-in, recovery and the indicator are all inside the experience shell, so client navigation keeps the draft. The email-link pages are separate documents by design: a draft in another tab stays there, and the pages say so (also for another device or browser).
* **Account switching is never silent** (PX-2b server rule, now with the designed page); the notice appears without any network call and viewing the page changes nothing.
* **Public registration stays unavailable**: no sign-up screen or link, `/account/sign-up` is 404, signup/magiclink links show "Registration is closed".
* The indicator is **provisional** (claims level): it says "Signed in", never "verified"; anything private still needs the server-verified check.

## 3a. Revision after review (two fixes and a wording correction)
1. **Stale session checks can no longer overwrite a newer sign-in or sign-out.** `session-coordinator.ts` (pure, no React or fetch) coordinates checks with auth actions: at most one check runs at a time and none starts during an action; an action first advances a generation counter, **cancels** the running check and **waits until it has settled** before sending its own request, so the two requests never overlap and their `Set-Cookie` headers cannot interleave; every check carries the generation it started in and the reducer discards a result from an older generation (defence in depth). Sign-in goes through the same path (`beginAuthAction()` before the request, `end()` in `finally`). Regressions: reducer test for both directions, **delayed-response tests for both directions** (a slow "anonymous" finishing after a sign-in; a slow "member" finishing after a sign-out), a no-overlap/ordering test, and two negative controls (generation check removed; action not waiting for the check) that make the tests fail. In a real browser (B5) the `/auth/session` response is held back with request interception, the member signs out (or in), the held response is then released: the new state stands, and with an expired token (so the held response carries rotated cookies) **no old session cookie returns**. Limit, stated plainly: this coordinates one tab; a different tab's check can still race (the provider's refresh-reuse interval tolerates it, but it is not a guarantee).
2. **No guarantee that an unavailable link is unused.** The provider may consume a one-time token before its response is lost, and a confirmed switch may already have revoked the previous session. The unavailable page now says: "We couldn’t confirm whether this completed. Try again. If the link has expired or was already used, request a new one." The earlier PX-2b results (the same link worked after a simulated outage) describe those test cases, not a promise.
3. The stale sidebar note "No AI, accounts or publishing yet" now reads "No AI or publishing yet. Accounts are by invitation."

## 4. Findings from building this
* **A real bug the script-based PX-2b checks could not see:** `Referrer-Policy: no-referrer` on the email-link pages made Chrome send `Origin: null` on the same-origin Continue POST, which the same-origin check correctly refused (HTTP 403) — a member would have been unable to use any emailed link. Fixed with `Referrer-Policy: same-origin` (nothing is sent to other sites); the spec and tests were updated.
* The browser's native `minlength` tooltip bypassed the designed weak-password message, so the password form now uses `novalidate` and shows the server's message.
* Layout: the top bar wraps on narrow screens so the chip is never clipped; full-page screenshots of sticky bars can show the page heading close to the bar (a capture artifact, not a layout overlap).

## 5. Limits and held items
Signed-in state is provisional; a session revoked elsewhere can still show as signed in until its token expires (T1 limitation, unchanged). Refresh still happens on `/auth/session` and T2 operations, not on every page navigation. A draft cannot move between devices or browsers. Not done: saving, AI, payments, migrations, hosted verification. **External testers still require real SMTP, real HTTPS cookie verification (the Secure flag cannot be seen over local HTTP) and confirmed hosted provider settings.** The eight-hour and seven-day session limits remain provisional. Artwork rights remain a public-release gate.
